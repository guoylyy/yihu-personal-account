# 设计：自由天数

> 状态：第一、二阶段已实现（v1.3.0），第三阶段未开始
> 日期：2026-10-30
> 思路来源：[FreeGrid](https://github.com/coni555/FreeGrid-Freedom)（理念与公式，代码不复用，见第 13 节）

## 1. 背景与目标

本系统已经回答了「我有多少、钱去哪了、按计划走没有」，但这些都是金额，不能直接帮人做决定。自由天数把它们翻译成一个问题：

> **如果今天起不再有工作收入，按现在的生活方式，手上的钱能撑多少天？**

目标：

1. 总览上有一个随账目自动变化的自由天数，不用额外设置目标
2. 决定花钱之前能看到代价，尤其是一次性支出和长期支出的区别
3. 每月知道天数变化的原因，不被市值波动带着走

非目标：

- 不做退休规划：不考虑通胀、投资收益率、寿命和社保养老金
- 不改变现有口径：净资产、个人支出、储蓄率的算法和接口都不动
- 不做评判：不给必要支出标代价，不用排名或扣分的语气

## 2. 现状与可复用的部分

| 已有 | 位置 | 用途 |
|---|---|---|
| 资产负债表 | `lib/networth.js` 的 `balanceSheet()` | 分子的来源；`investByType` 可以拆出储蓄险 |
| 月度个人支出 | `periodStats()` | 分母的来源；已剔除公司款和转移类，`byCategory` 带科目分组 |
| 净资产快照 | `NetWorthSnapshot.detail` | 月结时已存 `{ sheet, stats }`，历史分子可以直接读 |
| 月结检查 | `routes/close.js` 的 `checklist()` | 判断数据是否可信 |
| 借贷月供 | `Loan.monthlyPayment`、`annualRate` | 估算必还本金 |
| 应急金覆盖 | `Dashboard.vue`：`liquid ÷ 月预算` | **本设计要替换的卡片** |
| AI 只读工具 | `app.js` 的 `mountPlatform({ tools })` | 接入模拟决策 |

不新增并列指标：应急金覆盖和自由天数说的是同一件事，留两个只会让人困惑。

## 3. 口径

```
自由天数 = 可动用资金 ÷ 每日净消耗
每日净消耗 = (近 12 个月支出 + 12 个月必还本金 − 近 12 个月被动收入) ÷ 统计天数
```

同时计算两条线：

| | 分母里的支出 | 含义 |
|---|---|---|
| **生活线**（主数字） | 全部个人支出 | 维持现在的生活 |
| **生存线** | 只算「必要」组 | 只保必要开销 |

### 3.1 分子：可动用资金

```
可动用资金 = 现金 + 金融投资 − 储蓄险 − 信用卡欠款 − 无月供的无抵押借款
```

| 项目 | 处理 | 原因 |
|---|---|---|
| 现金、股票、基金、理财、定存 | 计入 | 能较快变现 |
| 储蓄险（`investByType.INSURANCE`） | 不计 | 退保损失大 |
| 股权、固定资产、应收 | 不计 | 变现不确定，自住房不能花 |
| 信用卡欠款 | 扣减 | 短期必还 |
| 借入、**没填月供**、非房贷车贷的借款 | 扣减 | 没有还款计划，按要全额归还算 |
| 借入、填了月供的借款 | 不扣 | 放进分母，避免重复计算 |
| `includeInNetWorth=false` 或 `TO_CONFIRM` | 不计 | 与 `balanceSheet()` 一致 |

现有 `sheet.liquid` 含储蓄险且不减负债，**保持不变**，新口径放在 `freedom.available`。

### 3.2 分母：支出

- **窗口**：截至上月的近 12 个完整月，不含当月，避免月初数字偏低
- **有效月**：支出大于 0 的月份。开始记账不满 12 个月时，用实际有效月
- **统计天数**：有效月的实际天数之和
- **生活线**：`periodStats().expense` 累加，已含未分类支出、已冲减退款
- **生存线**：`byCategory` 里 `group === '必要'` 的金额累加
- 不用预算：预算是计划数，且按「本人承担」折算过；用实际支出，分子分母都是「记进这本账的」

### 3.3 分母：必还本金

房贷车贷本金走 T5 转移，不算支出，但没有收入时仍要还。对每笔计入的 `BORROW` 借款：

```
月本金 = max(0, monthlyPayment − balance × annualRate ÷ 100 ÷ 12)
```

- `annualRate` 存的是百分数（3.85 表示 3.85%）
- 利息已在 A9 或 B1 里，这里只取本金，不重复
- `annualRate` 为空时，把整个月供当本金，并给出提示
- 房贷、车贷没填月供时按 0 计，并给出提示（数字会偏高）
- 未来的月供用当前的数，不模拟还清后的变化

### 3.4 分母：被动收入

- 第一阶段只算近 12 个月 `I5 投资收益`，即持仓分红的实际到账
- 不算 I4：其中混有退款、报销和借出利息
- 理财持有收益只体现在市值里，不计入，结果偏保守

第三阶段再支持标记其他被动收入，见第 10 节。

### 3.5 显示

- 内部单位是天，取整一律向下，差值用取整后的两端相减，同一屏数字能对上
- 见底日期 = 今天 + 天数
- 不足 365 天显示「N 天」；否则显示「X.X 年」，小字保留天数
- 净消耗小于等于 0 时显示「被动收入已覆盖」，不显示 ∞：被动收入可能来自分子里的资产，本金花掉后它也会消失

### 3.6 算例（虚构数据）

现金 20 万，金融投资 45 万（含储蓄险 5 万），信用卡欠款 1 万。近 12 个月（365 天）必要支出 25 万、弹性支出 11.5 万，月供本金 3000 元，分红 1.46 万。

```
可动用资金 = 200000 + 450000 − 50000 − 10000 = 590000
生活线：(250000 + 115000 + 36000 − 14600) ÷ 365 = 1058.63 元/天 → 557 天（1.5 年）
生存线：(250000 + 36000 − 14600) ÷ 365 = 743.56 元/天 → 793 天（2.1 年）
```

这组数据同时作为单元测试的基准。

## 4. 状态与可信度

| `state` | 条件 | 界面 |
|---|---|---|
| `INSUFFICIENT` | 有效月少于 3 个 | 「再记 N 个月就能算出来」，不显示数字 |
| `COVERED` | 净消耗小于等于 0 | 「被动收入已覆盖」 |
| `DEPLETED` | 可动用资金小于等于 0 | 0 天，并显示缺口 |
| `OK` | 其他 | 正常显示 |

可信度不改变数字，只在 `warnings` 里提示，并显示「数字可能不准」入口：

| `key` | 条件 | 影响 |
|---|---|---|
| `uncategorized` | 窗口内有未分类支出 | 生存线偏高 |
| `pendingBusiness` | 窗口内有待剥离公司款 | 分母已剔除，但现金未回 |
| `staleAccount` | 有账户超过 35 天没校准 | 分子不准 |
| `staleHolding` | 持仓市值超过 35 天没更新 | 分子不准 |
| `noMonthlyPayment` | 房贷车贷没填月供 | 天数偏高 |
| `noRate` | 有月供但没填年利率 | 本金偏高，天数偏低 |
| `spike` | 某月支出超过有效月中位数的 3 倍 | 一次性大额抬高了日均 |

## 5. 后端设计

### 5.1 `backend/src/lib/freedom.js`（新增）

纯计算和取数分开，纯函数不碰数据库，便于测试。

```js
// 纯函数
computeFreedom({ sheet, months, loans, now })
simulateFreedom(base, { oneOff, monthly, prepay })
attribute(prev, cur, monthNet)

// 取数（带租户过滤，走 resolveUid）
freedomOverview(uid)
freedomHistory(uid)
```

- 所有查询带 `userId`，遵守 `tenant.js` 的约定
- 口径只放这个文件，页面和 AI 工具都从这里取，不各算各的
- 不写流水，不需要改 `ledger.js`

### 5.2 接口

| 接口 | 说明 |
|---|---|
| `GET /api/pf/freedom` | 当前状态 |
| `GET /api/pf/freedom/history` | 月度趋势 |
| `GET /api/pf/freedom/simulate` | 模拟决策，只读 |

模拟用 GET：语义上只读，而且 `callSelf` 目前只支持 GET，AI 工具可以直接复用。

`GET /api/pf/freedom` 返回：

```jsonc
{
  "state": "OK",
  "available": 590000,
  "breakdown": { "cash": 200000, "investments": 400000, "creditDebt": 10000, "unsecuredDebt": 0 },
  "excluded": { "insurance": 50000, "equity": 0, "fixedAssets": 0, "receivables": 0 },
  "window": { "from": "2025-10", "to": "2026-09", "months": 12, "days": 365 },
  "daily": { "living": 1058.63, "survival": 743.56, "principal": 98.63, "passive": 40 },
  "days": { "living": 557, "survival": 793 },
  "depleteDate": { "living": "2028-05-09", "survival": "2028-12-31" },
  "passiveCoverage": 3.6,
  "warnings": [{ "key": "staleAccount", "text": "…", "link": "/accounts" }]
}
```

`passiveCoverage` 是被动收入占「支出 + 必还本金」的百分比。

### 5.3 对现有接口的改动

遵守「只增不改」：

- `GET /api/pf/dashboard`：增加 `freedom` 字段
- `POST /api/pf/close/snapshot`：`detail` 增加 `freedom`，冻结当月结果
- `GET /api/pf/close/summary`：增加「自由天数」一节

### 5.4 历史

分子不能事后重算，所以趋势读快照：

- 优先读 `detail.freedom`
- 老快照没有这个字段时，用 `detail.sheet` 算分子，用当时往前 12 个月的 `periodStats` 算分母。老数据的必还本金取不到，按 0 计，并标记 `approx: true`
- 没做月结的月份留空，不插值

可以批量查一次覆盖 36 个月的支出再滚动计算，避免每个点查 12 次。

### 5.5 AI 工具

在 `app.js` 增加两个只读工具：

| 工具 | 触发问题 |
|---|---|
| `get_freedom_overview` | 「我能撑多久」「还有多少自由天数」 |
| `simulate_decision` | 「买这台车会怎样」「每月多 500 的订阅影响多大」「提前还 10 万房贷划算吗」 |

要求：

- AI 只复述接口算出的数字，不自己算
- 回答必须带上一次性和长期的区别，以及「这是估算」
- 模拟不产生草稿、不落账

`routes/ai.js` 的问答上下文也带上 `freedom`，应用内的「问 AI」可以回答同类问题。

## 6. 前端设计

### 6.1 总览卡片

替换「应急金覆盖」卡：

```
自由天数
557 天                约 2028-05 见底
只保必要 793 天  ·  较上月 +12 天
```

点击打开详情抽屉：分子分母拆解、哪些资产没算进去、可信度提示、趋势图、模拟决策入口。

### 6.2 自由网格

- 用 CSS Grid 实现，不引入新依赖，颜色走现有样式变量
- 不足 1 年：1 格 = 1 天，最多 365 格；1 到 10 年：1 格 = 1 月；10 年以上：1 格 = 1 年
- 现金和投资用两种颜色，按金额比例分配，格数之和恒等于总格数
- 储蓄险、股权、固定资产显示为灰格，提示「有，但不算能花的钱」，不计入总数
- 手机端自动换行，遵守现有的响应式约定

### 6.3 代价显示

`这笔 ≈ 金额 ÷ 生活线每日净消耗`

- 只显示在**弹性组**科目上，必要组一律不显示
- 少于 1 天不显示，减少噪音
- 位置：流水详情、AI 草稿卡片、预算超支行（「超支 ¥2000 ≈ 2 天」）
- 状态不是 `OK` 时不显示
- 设置页提供开关，默认开

## 7. 模拟决策

```
GET /api/pf/freedom/simulate?oneOff=6000&monthly=500&loanId=12&prepay=100000
```

| 参数 | 对分子 | 对分母 |
|---|---|---|
| `oneOff` 一次性支出 | 减少 | 不变 |
| `monthly` 每月增减 | 不变 | 增减，折算到日 |
| `prepay` 提前还贷 | 减少；没有月供的无抵押借款已从分子扣过，不再减 | 按比例减少月供（`monthlyPayment × prepay ÷ balance`） |

一次性支出不摊进日均，这是和 FreeGrid 的主要区别：它把大额消费计入日均，结果随记账时长变化；这里只看这笔决策本身。

示例：可动用 60 万，年支出 12 万（365 天算）。

| 决策 | 一年花掉 | 自由天数 |
|---|---|---|
| 不变 | — | 1825 |
| 一次花 6000 | 6000 | 1806，少 19 天 |
| 每月多花 500 | 6000 | 1738，少 87 天 |

返回 `before`、`after`、`delta`（生活线和生存线都有），并注明「不写入账本」。提前还贷的月供按比例估算，具体以银行为准，文案要写明。

入口：详情抽屉里的表单、AI 助手对话。

## 8. 变化归因

月结时把当月变化拆成三部分，三项之和等于总变化：

```
结余影响     = 当月结余 ÷ 上月每日净消耗
市值及其他   = (可动用资金变化 − 当月结余) ÷ 上月每日净消耗
消耗变化影响 = 本月可动用资金 ÷ 本月每日净消耗 − 本月可动用资金 ÷ 上月每日净消耗
```

输出示例：「本月 +23 天：结余 +40，市值及其他 −10，开销变高 −7」。

「市值及其他」还包含公司款垫付和报销、资产买卖等，名称不能写成单纯的市值。

## 9. 里程碑

月结页增加「自由进度」，和现有的数据检查清单分开：

| 里程碑 | 条件 |
|---|---|
| 账目可信 | 有效月 ≥ 3，且无 `warnings` |
| 3 个月 | 生活线 ≥ 91 天 |
| 6 个月 | 生活线 ≥ 182 天 |
| 1 年 | 生活线 ≥ 365 天 |
| 3 年 | 生活线 ≥ 1095 天 |
| 被动覆盖 50% | `passiveCoverage` ≥ 50 |
| 被动覆盖 100% | `passiveCoverage` ≥ 100 |

```prisma
model Category    { isPassive Boolean @default(false) } // 其他被动收入，如房租
model Transaction { isOneOff  Boolean @default(false) } // 不计入日均的一次性大额
```

标了 `isOneOff` 的支出不进分母，但已经减少的现金仍体现在分子上。

## 11. 测试

`cd backend && npm test`，`AI_PROVIDER=stub`。新增 `test/freedom.test.mjs`。

纯函数：

- 第 3.6 节算例的生活线和生存线

接口：

- 租户隔离：A 用户读不到 B 用户的结果

## 13. FreeGrid 的取舍

| 取 | 不取 |
|---|---|
| 自由天数的概念 | 用净值做分子 |
| 自由网格 | 从开始记账算起的累计日均 |
| 下单前模拟 | 把一次性支出摊进日均 |
| 被动收入进公式 | 手填被动收入、∞ 的展示 |
| 自检清单和数据状态区分 | 「戴维斯三杀」式的文案 |
| 向下取整、日期按自然日的做法 | 纯本地、零网络 |
