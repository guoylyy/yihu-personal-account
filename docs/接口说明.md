# 接口说明（增量）

> 这里只记**新增 / 行为有变化**的接口与表结构，从 v1.2.0 开始。其余接口以 `backend/src/routes/*.js` 为准。
> 统一响应 `{ code, message, data }`：`code = 0` 成功；9002 参数 / 业务校验不通过；9004 不存在或无权访问。接口都在 `/api/pf` 下，需要登录，按当前用户隔离。

## v1.4.0

无 schema 变更。

### 新草稿类型

`POST /ai/parse`、`/ai/drafts`、`/ai/resolve` 的 `type` 多 7 种，都走 `POST /ai/drafts/:id/submit`，幂等规则不变。

| type | 字段 |
|---|---|
| `new_asset` | `assetName` `assetType` `amount`（估值）`purchasePrice` `date`（买入日期）`address` `description` |
| `new_account` | `accountName` `accountType` `amount`（余额，可为负）`date` `institution` `lastNo` `creditLimit` `billDay` `repayDay` |
| `set_budget` | `categoryCode` `year` `monthly` 或 `annual`，已有预算时覆盖 |
| `update_account` | `account`，改 `newName` `institution` `lastNo` `creditLimit` `billDay` `repayDay` `aliases` `status` `remark` |
| `update_holding` | `holding`，改 `newName` `code` `platform` `maturityDate` `annualRate` `remark` |
| `update_asset` | `asset`，改 `newName` `address` `purchaseDate` `purchasePrice` `status` `remark` |
| `update_loan` | `loan`，改 `counterparty` `kind` `monthlyPayment` `annualRate` `dueDate` `contractNo` `remark` |

- `update_*` 的目标：名称在当前用户的列表里唯一命中 > 唯一的 @ 引用。模型或请求带的 `targetId` 不算数；重名、对不上时 `/ai/parse` 不出草稿，返回 `question`。提交时目标只认落库的
- `annualRate` 是百分数，3.85% 填 3.85
- `new_loan` 多 `monthlyPayment` `annualRate` `dueDate`，`kind` 多 `CAR` `CONSUMER`
- 修复：`balance` 草稿的负数金额在 `/ai/parse`、`/ai/resolve` 里被转成正数

`POST /ai/ask` 的上下文多账户、持仓、固定资产、借贷明细。

## v1.3.0

新增，全部只读。口径见 `docs/设计-自由天数.md` 和 `backend/src/lib/freedom.js`。

### `GET /freedom`

`state`：`OK` / `COVERED`（被动收入已覆盖，`days` 为 `null`）/ `DEPLETED`（可动用资金 ≤ 0，`days` 为 0）/ `INSUFFICIENT`（有效月不足 3 个，`need` 是还差几个月，`daily` `days` `depleteDate` 为 `null`）。生活线和生存线可能状态不同：`days.survival` 单独为 `null` 表示只有生存线被覆盖。

```jsonc
{
  "state": "OK",
  "available": 590000,
  "breakdown": { "cash": 200000, "investments": 400000, "creditDebt": 10000, "unsecuredDebt": 0 },
  "excluded": { "insurance": 50000, "equity": 0, "fixedAssets": 0, "receivables": 0 },
  "window": { "from": "2025-10", "to": "2026-09", "months": 12, "days": 365 },
  "totals": { "living": 365000, "survival": 250000, "principal": 36000, "passive": 14600 },
  "daily": { "living": 1058.63, "survival": 743.56, "principal": 98.63, "passive": 40 },
  "days": { "living": 557, "survival": 793 },
  "depleteDate": { "living": "2028-05-09", "survival": "2028-12-31" },
  "passiveCoverage": 3.6,
  "loans": [{ "id": "1", "counterparty": "建行房贷", "kind": "MORTGAGE", "balance": 1000000, "monthlyPayment": 6000, "monthlyPrincipal": 3000 }],
  "warnings": [{ "key": "staleAccount", "text": "…", "link": "/accounts" }]
}
```

`warnings[].key`：`uncategorized` `pendingBusiness` `staleAccount` `staleHolding` `noMonthlyPayment` `noRate` `spike`。只提示，不改变数字。

### `GET /freedom/simulate`

参数都可选：`oneOff`（≥ 0）、`monthly`（可为负）、`loanId` + `prepay`（≥ 0，不超过未还本金）。返回 `state`、`before`、`after`、`delta`、`note`，不写流水、不产生草稿。`delta` 里任一端是「已覆盖」时为 `null`。数据不足时 `state = INSUFFICIENT`，`before` `after` `delta` 为 `null`。参数不合法、借款不是自己的返回 9002。

### 字段只增

- `GET /dashboard` 多 `freedom`，结构同 `GET /freedom`
- `POST /close/snapshot` 的 `detail` 多 `freedom`
- `GET /close/summary` 多「五、自由天数」，「待核实」顺延为第六节
- `GET /transactions` 的 `category` 多 `groupName`

## v1.2.2

`POST /ai/parse` 响应多 `notice`：给用户看的一句话，正常时为 `null`。规则兜底时是「AI 暂时不可用，已用规则解析」；只传截图又调不通、模型不支持看图、AI 没开时说明具体原因。`error` 是给人看的失败原因，不含原始异常。

`POST /ai/ask` 模型调不通时返回 `code = 0`，`answer` 里说明原因，并带 `error`。AI 没开时行为不变（`code = 9001`）。

`GET /ai/status` 的 `provider` 多 `platform`；`model` 在第一次调通前是「平台默认模型」或 `AI_MODEL`，之后是平台返回的模型名。

## v1.2.0

### 新增表

**`AiDraft`**：草稿，每条待入账内容一行。

| 字段 | 说明 |
|---|---|
| `userId` | 归属用户 |
| `type` | 类型，见 `ITEM_TYPES`，本版新增 `update_transaction` |
| `targetId` | 修改流水时要改的流水 id，只认落库时解析出来的 |
| `payload` | 草稿内容（JSON） |
| `batchSeq` | 同一批解析里内容相同的第几条，从 0 开始，默认 0 |
| `logId` | 对应的 `AiEntryLog` |
| `submittedAt` / `resultId` / `resultCode` | 提交时间、业务记录 id、流水编号或摘要 |
| `duplicateOf` | 被判重复时，第一次提交的草稿 id |
| `lockedAt` | 提交进行中的锁 |

**`AiSubmission`**：提交指纹。

| 字段 | 说明 |
|---|---|
| `fingerprint` | **唯一索引**。`sha256(类型 + 用户 id + 键排序 JSON)`，JSON 只含写进账本的字段（把握度、备注、警告不算），金额按数字比较，含 `targetId` 和 `batchSeq` |
| `status` | `PENDING` 处理中 / `DONE` 成功 / `FAILED` 失败（可重试） |
| `resultId` / `resultCode` | 第一次的结果 |
| `claimedAt` | 本轮提交开始时间，60 秒窗口从这里算 |

只新增表，不动已有字段，`prisma db push` 无数据风险。

### `POST /ai/drafts`（新增）

草稿落库。

请求：`{ items: [...] }` 或 `{ item: {...} }`，可带 `context`（格式同下）。一次最多 100 条。
返回：`{ draftId, items, question }`。`items` 每条带 `draftId`；只有一条时顶层也给 `draftId`。定不下修改目标的条目不落库，原因在 `question`。

### `GET /ai/drafts/:id`（新增）

返回 `{ draftId, type, targetId, status, submitted, submittedAt, id, code, duplicateOf, payload }`。`status` 是 `PENDING` 或 `SUBMITTED`；`id` / `code` 是入账结果。别人的草稿和不存在的响应相同（9004）。

### `POST /ai/drafts/:id/submit`（新增）

确认入账。请求：`{ item? }`，用户在卡片上改过就带上，不带用落库内容。类型可在新增类之间切换；修改目标只认落库的，请求里的 `targetId` 无效；普通草稿不能改成 `update_transaction`。

返回：`{ draftId, type, targetId, status, submitted, submittedAt, id, code, duplicateOf, duplicate, originalId, originalDraftId }`。

| 场景 | 结果 |
|---|---|
| 同一草稿再次提交（不限时间，含并发） | 第一次的 `id` / `code`，`duplicate: true` |
| 内容相同的另一张草稿，60 秒内 | 第一次的 `id` / `code`，`duplicate: true`，`originalDraftId` 指向第一张 |
| 内容相同的另一张草稿，超过 60 秒 | 新的一笔，`duplicate: false` |
| 同一批解析里内容相同的多条 | 各记一笔。同一批重新解析再提交时，按第几条对上上一次，判重复 |
| 缺字段 / 越权 / 账户不存在 | 9002 或 9004，草稿不标记已提交，改好可重提 |

做法：草稿锁（条件更新）排队同一张草稿的并发；指纹靠唯一索引直接插入，冲突再回查，不是先查再写。

### `POST /ai/parse`（行为变化，字段只增）

- 多收 multipart 字段 `context`（JSON 串）：`{ route, filters: { period, account_id, category_id, scope, direction }, pinned: [{ type, id }] }`。`type` 取 `transaction` / `account` / `holding` / `asset` / `loan`，最多 10 条
- `items` 每条多 `draftId`、`missing`，可能多 `refSource`（字段来自 `pinned` 还是 `filter`）
- 多返回 `question`：不确定时的反问，此时可能没有草稿
- **`pinned` 里有不存在、越权或格式非法的记录：返回 9004，不调模型、不出草稿**。不存在和越权响应相同
- `filters` 里的账户、科目不属于当前用户时当作没选；未登记的 `route` 不进提示词

解析优先级：用户明确说的 > `@` 引用的 > 当前页筛选 > 不确定就问。提示词和 `lib/aiContext.js` 的 `applyRefs` 行为一致；模型给的 `targetId` 不在 `@` 里时不采用，防止它编 id 改到别的记录。

### `POST /ai/resolve`（字段只增）

路径、请求和原字段不变。每条多 `missing`：入不了账的字段名数组，如 `["amount"]`。`warnings` 不变。修复：只带 `categoryId` 没带 `categoryCode` 时不再被清空。

### `GET /ai/status`（字段只增）

`types` 多 `update_transaction`；`AI_PROVIDER=stub` 时 `provider` 为 `stub`。

### `POST /ai/commit`（保留）

路径和返回不变，但**不幂等**，只为兼容保留，前端已改用 `drafts/:id/submit`。

### 新草稿类型 `update_transaction`

改已有流水，不新建。字段：`targetId`、`targetCode`、`targetSummary`、`targetCounterparty`、`targetLinked`，加上要改的 `date`、`direction`、`amount`、`accountId`、`categoryId`、`counterparty`、`description`、`isBusiness`、`businessOrg`，没给的不改。

### 流水写入校验（行为变化）

`POST /transactions`、`PUT /transactions/:id`、互转、持仓交易的资金账户、借贷还款、AI 入账都校验账户和科目属于当前用户，否则报「账户不存在或无权访问」。此前这几处不校验，带别人的 id 能写进去。
