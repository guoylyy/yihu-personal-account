# 接口说明（增量）

> 这里只记**新增 / 行为有变化**的接口与表结构，从 v1.2.0 开始。其余接口以 `backend/src/routes/*.js` 为准。
> 统一响应 `{ code, message, data }`：`code = 0` 成功；9002 参数 / 业务校验不通过；9004 不存在或无权访问。接口都在 `/api/pf` 下，需要登录，按当前用户隔离。

## v1.2.0

### 新增表

**`AiDraft`**：草稿，每条待入账内容一行。

| 字段 | 说明 |
|---|---|
| `userId` | 归属用户 |
| `type` | 类型，见 `ITEM_TYPES`，本版新增 `update_transaction` |
| `targetId` | 修改流水时要改的流水 id，只认落库时解析出来的 |
| `payload` | 草稿内容（JSON） |
| `batchSeq` | 同一批解析里内容相同的第几条，从 0 开始，默认 0 |
| `logId` | 对应的 `AiEntryLog` |
| `submittedAt` / `resultId` / `resultCode` | 提交时间、业务记录 id、流水编号或摘要 |
| `duplicateOf` | 被判重复时，第一次提交的草稿 id |
| `lockedAt` | 提交进行中的锁 |

**`AiSubmission`**：提交指纹。

| 字段 | 说明 |
|---|---|
| `fingerprint` | **唯一索引**。`sha256(类型 + 用户 id + 键排序 JSON)`，JSON 只含写进账本的字段（把握度、备注、警告不算），金额按数字比较，含 `targetId` 和 `batchSeq` |
| `status` | `PENDING` 处理中 / `DONE` 成功 / `FAILED` 失败（可重试） |
| `resultId` / `resultCode` | 第一次的结果 |
| `claimedAt` | 本轮提交开始时间，60 秒窗口从这里算 |

只新增表，不动已有字段，`prisma db push` 无数据风险。

### `POST /ai/drafts`（新增）

草稿落库。

请求：`{ items: [...] }` 或 `{ item: {...} }`，可带 `context`（格式同下）。一次最多 100 条。
返回：`{ draftId, items, question }`。`items` 每条带 `draftId`；只有一条时顶层也给 `draftId`。定不下修改目标的条目不落库，原因在 `question`。

### `GET /ai/drafts/:id`（新增）

返回 `{ draftId, type, targetId, status, submitted, submittedAt, id, code, duplicateOf, payload }`。`status` 是 `PENDING` 或 `SUBMITTED`；`id` / `code` 是入账结果。别人的草稿和不存在的响应相同（9004）。

### `POST /ai/drafts/:id/submit`（新增）

确认入账。请求：`{ item? }`，用户在卡片上改过就带上，不带用落库内容。类型可在新增类之间切换；修改目标只认落库的，请求里的 `targetId` 无效；普通草稿不能改成 `update_transaction`。

返回：`{ draftId, type, targetId, status, submitted, submittedAt, id, code, duplicateOf, duplicate, originalId, originalDraftId }`。

| 场景 | 结果 |
|---|---|
| 同一草稿再次提交（不限时间，含并发） | 第一次的 `id` / `code`，`duplicate: true` |
| 内容相同的另一张草稿，60 秒内 | 第一次的 `id` / `code`，`duplicate: true`，`originalDraftId` 指向第一张 |
| 内容相同的另一张草稿，超过 60 秒 | 新的一笔，`duplicate: false` |
| 同一批解析里内容相同的多条 | 各记一笔。同一批重新解析再提交时，按第几条对上上一次，判重复 |
| 缺字段 / 越权 / 账户不存在 | 9002 或 9004，草稿不标记已提交，改好可重提 |

做法：草稿锁（条件更新）排队同一张草稿的并发；指纹靠唯一索引直接插入，冲突再回查，不是先查再写。

### `POST /ai/parse`（行为变化，字段只增）

- 多收 multipart 字段 `context`（JSON 串）：`{ route, filters: { period, account_id, category_id, scope, direction }, pinned: [{ type, id }] }`。`type` 取 `transaction` / `account` / `holding` / `asset` / `loan`，最多 10 条
- `items` 每条多 `draftId`、`missing`，可能多 `refSource`（字段来自 `pinned` 还是 `filter`）
- 多返回 `question`：不确定时的反问，此时可能没有草稿
- **`pinned` 里有不存在、越权或格式非法的记录：返回 9004，不调模型、不出草稿**。不存在和越权响应相同
- `filters` 里的账户、科目不属于当前用户时当作没选；未登记的 `route` 不进提示词

解析优先级：用户明确说的 > `@` 引用的 > 当前页筛选 > 不确定就问。提示词和 `lib/aiContext.js` 的 `applyRefs` 行为一致；模型给的 `targetId` 不在 `@` 里时不采用，防止它编 id 改到别的记录。

### `POST /ai/resolve`（字段只增）

路径、请求和原字段不变。每条多 `missing`：入不了账的字段名数组，如 `["amount"]`。`warnings` 不变。修复：只带 `categoryId` 没带 `categoryCode` 时不再被清空。

### `GET /ai/status`（字段只增）

`types` 多 `update_transaction`；`AI_PROVIDER=stub` 时 `provider` 为 `stub`。

### `POST /ai/commit`（保留）

路径和返回不变，但**不幂等**，只为兼容保留，前端已改用 `drafts/:id/submit`。

### 新草稿类型 `update_transaction`

改已有流水，不新建。字段：`targetId`、`targetCode`、`targetSummary`、`targetCounterparty`、`targetLinked`，加上要改的 `date`、`direction`、`amount`、`accountId`、`categoryId`、`counterparty`、`description`、`isBusiness`、`businessOrg`，没给的不改。

### 流水写入校验（行为变化）

`POST /transactions`、`PUT /transactions/:id`、互转、持仓交易的资金账户、借贷还款、AI 入账都校验账户和科目属于当前用户，否则报「账户不存在或无权访问」。此前这几处不校验，带别人的 id 能写进去。
